2. Бизнес-процессы

Ниже перечислены основные процессы, которые поддерживает платформа. Это и клиентские сценарии, и административные операции, и сервисные фоновые операции.

Финансы AML Поддержка QR

Авторизация и доступ

Access control
  • Вход в систему — пользователь или администратор вводит учетные данные и запускает авторизацию, чтобы попасть в нужную часть системы.
  • Проверка доступа — backend проверяет логин, пароль и токен, затем определяет роль пользователя и разрешённые ему разделы.
  • Фиксация входа — после успешной проверки сохраняются последний логин, устройство и IP-адрес для последующего контроля безопасности.

Профиль клиента и кошельки

Profile
  • Запрос профиля — приложение обращается к backend и получает карточку клиента с его основными данными.
  • Загрузка балансов — backend возвращает кошельки, категорию, тариф, резидентство и актуальные суммы по всем валютам.
  • Синхронизация настроек — обновляются push-параметры и токены уведомлений, чтобы клиент получал сообщения без потерь.

Переводы

Transfers
  • Выбор получателя — клиент указывает телефон или кошелёк, выбирает валюту и вводит сумму перевода.
  • Проверка операции — backend проверяет реквизиты, лимиты, баланс и комиссию, чтобы исключить ошибочную транзакцию.
  • Проведение перевода — выполняется списание и зачисление, после чего операция сразу попадает в историю пользователя.

Конвертация валют

Swap
  • Выбор пары — пользователь выбирает валюту списания и валюту получения, затем вводит сумму для обмена.
  • Расчёт суммы — backend применяет курс, рассчитывает комиссию и проверяет ограничения по минимуму и максимуму.
  • Завершение свопа — списание и зачисление выполняются одной связанной транзакцией с записью в историю операций.

Комиссии и тарифы

Fees
  • Изменение тарифа — администратор корректирует процент или фиксированную сумму для конкретного вида операции.
  • Сохранение правки — backend записывает новое значение, комментарий и создаёт запись в истории изменений.
  • Применение расчёта — обновлённые значения сразу используются для всех новых операций без ручного вмешательства.

AML / antifraud

Compliance
  • Настройка правил — администратор включает или отключает правила для категорий K1–K6 и задаёт нужные параметры контроля.
  • Срабатывание проверки — при нарушении условия backend создаёт кейс на ручную проверку и отправляет его в раздел финконтроля.
  • Решение по кейсу — администратор подтверждает либо отклоняет операцию, и это решение влияет на обработку похожих случаев в дальнейшем.

История и выписки

Statements
  • Поиск операций — фильтры применяются по клиенту, валюте, периоду и типу операции, чтобы быстро сузить выборку.
  • Просмотр деталей — интерфейс показывает найденные транзакции, квитанции и основные параметры каждой операции.
  • Экспорт отчётов — выбранные данные формируются в CSV, PDF или TXT и могут быть сохранены отдельно.

Поддержка и уведомления

Support
  • Создание обращения — пользователь отправляет сообщение в чат поддержки, если ему нужна помощь или уточнение по работе сервиса.
  • Ответ администратора — тикет появляется в панели и обрабатывается в том же потоке, чтобы диалог не терялся и оставался привязанным к клиенту.
  • Уведомления — система отправляет push-сообщения и хранит историю переписки, чтобы можно было поднять контекст обращения.

Блокчейн-операции

Blockchain
  • Проверка ноды — backend контролирует состояние TRON-узла, его синхронизацию и доступность сети перед операциями.
  • Работа с treasury — выполняются операции по депозиту, свипу и reconcile для USDT, чтобы деньги не зависали на промежуточных адресах.
  • Фиксация результата — результат операции записывается в базу и отражается в резервных балансах для дальнейшего контроля.

Управление администраторами

Admins
  • Создание доступа — супер-администратор создаёт нового сотрудника и назначает ему роль.
  • Настройка прав — система ограничивает видимые разделы и действия в зависимости от роли администратора.
  • Контроль активности — изменения, входы и ключевые действия администратора попадают в аудит-логи.

Аудит действий

Audit
  • Фиксация событий — backend записывает действия администраторов, чтобы можно было восстановить цепочку изменений.
  • Просмотр истории — в админке доступны список действий, время события, инициатор и краткое описание изменения.
  • Экспорт данных — аудит можно выгружать для внутренней проверки и отчётности.

Системные настройки

Settings
  • Обновление параметров — администратор меняет системные лимиты, правила обработки и внешние подключения.
  • Сохранение конфигурации — backend сохраняет новые параметры и сразу использует их в следующих запросах.
  • Применение настроек — изменения влияют на тарифы, отображение данных и обработку операций без перезапуска системы.

Курсы валют

Rates
  • Изменение курса — администратор задаёт курс покупки и продажи USD в отдельном разделе.
  • Использование курса — backend подставляет актуальные значения при конвертации и расчёте сумм.
  • История изменений — все правки фиксируются с комментарием и отображаются в журнале изменений.

Резервы и банковские балансы

Reserves
  • Сбор балансов — backend получает живые остатки по счетам ЦБ, банка и партнёров.
  • Обновление резервов — суммы обновляются после комиссий, переводов и блокчейн-операций.
  • Контроль остатков — администратор видит, хватает ли средств для дальнейших выплат и внутренних расчётов.

Tron-wallet

Wallet
  • Показ кошелька — сервис отображает закреплённый TRON-кошелёк и его текущее состояние.
  • Обновление баланса — по запросу подтягиваются актуальные данные без изменения самой привязки кошелька.
  • Сервисные операции — кошелёк используется как технический инструмент для перевода и контроля blockchain-средств.

Push-уведомления

Push
  • Отправка события — backend формирует push при важной операции или сервисном действии.
  • Доставка на устройство — уведомление уходит в Firebase и приходит на мобильный клиент.
  • Хранение истории — уведомления сохраняются, чтобы пользователь мог позже открыть их список и детали.

3. Требования к системе

Для стабильной работы системы нужна серверная среда, отдельная база данных, кэш, TRON-узел и подключение к внешним сервисам, которые используются приложениями.

Серверная часть

Компонент Требование
Runtime Node.js 20+
База данных PostgreSQL 13+
Кэш / очереди Redis 6+
TRON Full node / witness node, доступный по HTTP
Хранилище S3-совместимое хранилище или MinIO
Почта SMTP-сервер для системных писем

Веб-админка

Компонент Требование
Runtime Node.js 20+
Фреймворк Next.js 15 + React 19
Сборка Docker или локальный npm build
API доступ Backend endpoint через переменные окружения

Дополнительные зависимости

  • Git для получения исходников
  • Docker Engine и Docker Compose для серверных компонентов
  • Права на чтение/запись `.env` и секретов
  • Камера и хранилище на мобильном устройстве для QR-функций
  • Стабильный доступ к интернету и DNS
Рекомендуется поднимать backend, админку и мобильный клиент в единой инфраструктуре, чтобы все API-эндпоинты, push-уведомления, блокчейн-узлы и хранилища были доступны без ручных обходных схем.
